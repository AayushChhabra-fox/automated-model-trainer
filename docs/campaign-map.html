Automated Model Trainer · campaign anatomy

One hypothesis, one frozen champion, one honest answer

A campaign moves across three lanes: the human who owns the decision, the agents running in the local CLI, and Databricks doing every unit of compute. Four checkpoints belong to the human; everything between the third and fourth runs on its own inside the agreed budget.

What QA can say

Phase 0 only

INVALID_EXPERIMENT

The artifact or evaluation path is broken. Fix the defect and rerun Phase 0 — architecture, features, hyperparameters and model choice stay untouched.

Phase 1

PASS

Meets the acceptance criteria set before QA ran. Register as candidate; proceed to online A/B or shadow evaluation.

Phase 1

FAIL_HYPOTHESIS

Won on validation, did not generalize. Recorded as a finding. The same model's search is not reopened with QA feedback.

Phase 1

SPEC_REVIEW

Evidence that labels, population, candidates or metrics are wrong. Back to the human before anything in the spec or contract changes.

Where things live

MLflow

Everything about a run

Params, per-epoch curves, validation and QA metrics, model artifacts, result.json, the final report. Tagged with campaign, hypothesis, contract_hash, harness version, code version.

Delta tables

Only the ground truth

Materialized split_train, split_validation, split_qa, pinned by Delta version and a membership hash. Source tables are read, never copied per experiment.

Orchestrator state

Just enough to resume

Stage, approvals, current hypothesis, budget, run IDs, frozen champion reference. A SQLite checkpoint per campaign; amt resume picks up mid-loop.

Rules enforced in code, not prose

  1. One contract per campaign. contract_hash is stamped at HC3; every node and every job asserts it before doing work.
  2. Splits are immutable. Jobs read VERSION AS OF and verify row counts against the contract.
  3. Train jobs cannot see QA. SplitGuard raises on any read outside the role's allow-list.
  4. QA needs a freeze. Routing refuses Phase 0 unless exactly one FrozenChampion exists; the Trainer cannot re-enter after freeze.
  5. Same math for everyone. A single versioned evaluation harness scores baseline, candidates and QA; QA loads the model through MLflow pyfunc, not the trainer's in-memory object.
  6. Bounded loops. The trainer stops at max_iterations or compute budget regardless of what the agent proposes; Phase 0 retries are capped at three.
